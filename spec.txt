**Tech Spec: Файловый менеджер проекта**

**1. Цель**
Сделать файловый менеджер для проекта с UX, вдохновленным `Windows Explorer` и `Google Drive`: навигация по папкам, создание и управление сущностями проекта, локальный/глобальный поиск, избранное, корзина, теги, инспектор справа, поддержка массовых операций и удобная keyboard/mouse-навигация.

**2. Технологический стек**
- Frontend: `Vue 3`, `TypeScript`, `Pinia`, `Vue Router`
- Backend: `Django` + REST API
- DB: `MongoDB`
- Архитектурный принцип: `Node` как основная сущность файлового менеджера

**3. Область ответственности**
- `/projects` — главная залогиненного пользователя со списком проектов
- `/project/:projectId` и вложенные маршруты — файловый менеджер внутри проекта
- `Document` и `Canvas` на данном этапе считаются черновиками/stub editor pages

**4. Основные сущности**
```ts
type NodeType = 'folder' | 'document' | 'canvas'

interface Node {
  id: string
  project_id: string
  parent_id: string | null
  type: NodeType

  title: string
  icon: string | null
  tag_ids: string[]

  is_favorite: boolean
  is_deleted: boolean

  created_at: string
  created_by: string
  updated_at: string
  updated_by: string
}
```

```ts
interface Tag {
  id: string
  project_id: string
  name: string
  color: {
    hex: string
    rgba: string
  }
}
```

```ts
interface DocumentDraft {
  id: string
  node_id: string
  blocks: unknown[]
}
```

```ts
interface CanvasDraft {
  id: string
  node_id: string
  elements: unknown[]
}
```

```ts
interface ClipboardState {
  type: 'copy' | 'cut' | null
  nodeIds: string[]
  sourceProjectId: string | null
  sourceParentId: string | null
}
```

Рекомендация для 2 этапа:
- добавить в `Node` поля `deleted_at`, `deleted_by`
- это нужно для автоочистки корзины через 30 дней и истории восстановления

**5. Маршруты**
- `/projects`
- `/project/:projectId`
- `/project/:projectId/folder/:folderId`
- `/project/:projectId/document/:documentId`
- `/project/:projectId/canvas/:canvasId`

Query params:
- `?view=list | grid`
- `?sort=name | created | updated | type`
- `&order=asc | desc`
- `&search=...`

**6. UI-структура**
`Projects page`
- список всех проектов пользователя
- карточка проекта: баннер, название, дата последнего изменения
- topbar: аватар, имя, уведомления, поиск, `Создать проект`
- sidebar: `Все проекты`, команды, `Избранное`, `Корзина`

`Project explorer`
- topbar: `назад`, `вперед`, `вверх`, `перезагрузка`, breadcrumbs/path, поиск
- left sidebar: дерево папок, избранное, корзина, список тегов
- main toolbar: `Создать`, `Вырезать`, `Копировать`, `Вставить`, `Переименовать`, `Удалить`, `Сортировать`, `Вид`
- main area: список/карточки файлов и папок
- right sidebar: сведения о текущей папке или выбранном объекте

**7. Поведение навигации**
- `Назад/вперед` используют `router history`
- `Вверх` использует отдельную логику: переход к `parent_id`
- `Перезагрузка` повторно запрашивает текущую директорию с сервера
- breadcrumbs строятся по текущему маршруту и кэшу папок

**8. Поведение выбора и действий**
- `single click` → select
- `double click` → open
- `Ctrl` → toggle selection
- `Shift` → range selection
- `click outside` → clear selection
- `Enter` → открыть один выбранный объект
- `F2` → rename
- `Delete` → удалить
- `Ctrl+C / Ctrl+X / Ctrl+V` → clipboard actions

**9. Pinia stores**
`useProjectsStore`
- список проектов
- загрузка `/projects`
- создание проекта

`useFileManagerStore`
- текущий проект
- текущая директория
- nodes текущей папки
- cache ранее открытых папок
- view/sort/order/search/loading/error

`useSelectionStore`
- selected ids
- anchor id для `Shift`
- single/multi select logic

`useClipboardStore`
- `copy`, `cut`, `paste`, `clear`
- состояние проектного буфера обмена

`useTagsStore`
- список тегов проекта
- создание/редактирование/удаление тегов
- автокомплит

`useTreeStore`
- какие папки раскрыты
- какие ветки уже lazy-loaded

`useUiStore`
- модалки
- контекстные меню
- настройки пользователя
- правый инспектор

`useSearchStore`
- строка поиска
- parsed tokens
- dropdown state
- debounce 300ms

**10. API**
Проекты:
- `GET /projects`
- `POST /projects`

Узлы:
- `GET /projects/:projectId/nodes?parent_id=:id&view=list&sort=updated&order=desc&search=...`
- `POST /projects/:projectId/nodes`
- `PATCH /projects/:projectId/nodes/:nodeId`
- `DELETE /projects/:projectId/nodes/:nodeId`
- `POST /projects/:projectId/nodes/bulk-delete`
- `POST /projects/:projectId/nodes/move`
- `POST /projects/:projectId/nodes/copy`
- `POST /projects/:projectId/nodes/duplicate`
- `POST /projects/:projectId/nodes/favorites`

Дерево и теги:
- `GET /projects/:projectId/tree?parent_id=:id`
- `GET /projects/:projectId/tags`
- `POST /projects/:projectId/tags`
- `PATCH /projects/:projectId/tags/:tagId`
- `DELETE /projects/:projectId/tags/:tagId`

Черновики:
- `GET /projects/:projectId/documents/:documentId`
- `GET /projects/:projectId/canvases/:canvasId`

**11. Серверная валидация**
Создание:
- пустое имя → `400`
- дубликат имени в одной директории → `409`
- нет прав → `403`

Удаление:
- удаление = `is_deleted = true`
- объект исчезает из обычных папок и появляется в корзине

Move / cut / paste:
- пока базовая серверная валидация:
- все `nodeIds` должны существовать в рамках `project_id`
- target folder должен существовать в рамках `project_id`
- у пользователя должен быть доступ ко всем исходным узлам и целевой папке
- если что-то невалидно → блокировать запрос

Рекомендация на будущее:
- отдельно добавить защиту от перемещения папки в саму себя или в потомка

**12. Поиск**
Режимы:
- в корне проекта: глобальный поиск по проекту
- внутри папки: локальный по текущей директории

Поддерживаемые токены:
- `name:`
- `tags:`
- `type:`
- `created_by:`
- `date:`

Требование:
- поиск реализуется как parser строки, а не как plain text search
- debounce: `300ms`
- `Enter` → применить
- `Escape` → очистить
- click outside → закрыть dropdown

Автокомплит:
- `tags:` — список тегов, сортировка по совпадению
- `type:` — folder/document/canvas
- `created_by:` — участники проекта
- `date:` — range picker + ручной ввод `dd.mm.yyyy`

**13. Корзина**
Текущее поведение:
- soft delete через `is_deleted: boolean`
- удаленные элементы видны только в корзине

План 2 этапа:
- контекстное меню на корзине:
- `Восстановить все`
- `Очистить все`
- опционально автоудаление через 30 дней после soft delete
- для автоудаления желательно добавить `deleted_at`

**14. Теги**
- теги проектные, общие для всех узлов проекта
- если пользователь создает объект с новым тегом, которого еще нет:
- тег создается автоматически
- цвет назначается случайно
- редактирование и удаление тегов доступно через sidebar
- создание/редактирование тега: `name`, цвет из списка или кастомный color picker с `rgba` и `hex`

**15. Производительность**
- lazy loading дерева папок
- загружается только текущая папка и открытые ветки дерева
- не загружается весь проект сразу
- кэш последних открытых папок в store
- MongoDB индексы:
- `project_id`
- `parent_id`
- `tag_ids`
- `created_at`
- `updated_at`
- виртуализация списка при `>100` элементов

**18. Критерии готовности**
- пользователь может открыть проект и перемещаться по папкам
- список папок и файлов стабильно синхронизирован с route
- create/rename/delete/favorite работают через API и корректно обновляют store
- search, sort и view отражаются в UI и query params
- lazy loading дерева не тянет весь проект
- удаленные элементы скрыты из обычных папок и доступны в корзине
- clipboard и массовые действия не проходят без серверной валидации
